# Row-Level Access Control (RLS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add opt-in, per-entity row-level access control — an entity declares one many-to-one relationship as its ownership column (`owner: true`), or opts a many-to-one relationship into inheriting ownership transitively from its target (`cascades_ownership: true`), and every generated CRUD operation on that entity is automatically filtered to rows the current caller owns, with a declared set of roles that bypass filtering entirely.

**Architecture:** `translate.py` resolves, per entity, one of *unowned* / *root-owned* / *cascade-owned*, producing a single `rls` dict (or `None`) attached to both `data_models` entries and per-module `crud_entities` entries — the same precedent as `owned_relationships`/`many_to_many_relationships`. `repo.py.jinja` gains an `owner_id: Optional[int] = None` parameter on `get_<x>_by_id`/`get_all_<x>s`/`update_<x>`/`delete_<x>` (root: a `WHERE`; cascade: `JOIN`s up the resolved chain then the same `WHERE` on the root's FK column); `create_<x>` needs no repo-layer change. `module_service.py.jinja` threads `owner_id` through, injects the owner value into the payload on `create` for root-owned entities, and reuses the existing FK-existence-validation mechanism — made owner-aware — for a cascade-owned entity's linking FK. `module_routes.py.jinja` resolves `owner_id` per identity source (`auth_user` via `require_roles`/`get_current_user`, `header` via a required FastAPI `Header`) and computes the bypass. `module_schemas.py.jinja` drops the owner FK from `<Entity>Create`/`<Entity>Update` for root-owned entities. Every template change branches on `database.async_mode` using this codebase's established sync/async conventions (already merged from the async-support plan).

**Tech Stack:** Python 3.11, Jinja2 (`trim_blocks`/`lstrip_blocks` — see Global Constraints), SQLAlchemy 2.0.23 (legacy `Query` API and `sqlalchemy.ext.asyncio`, both already in use), FastAPI, pytest.

**Spec:** `docs/superpowers/specs/2026-09-10-rls-design.md`

## Global Constraints

- **The resolved `rls` structure (produced by Task 3, consumed by every later task — stated here verbatim so no task re-derives it):**
  ```python
  {
      "is_root": bool,               # True if THIS entity carries owner:true; False if cascade-owned
      "root_model": str,             # entity name carrying owner:true (== this entity's own name if is_root)
      "owner_fk_column": str,        # FK column name, on root_model's table, pointing to the owner entity
      "join_chain": [                # [] when is_root is True (direct WHERE, no JOIN)
          {
              "from_model": str,     # entity owning this hop's FK column
              "from_fk_column": str, # FK column name on from_model
              "to_model": str,       # entity this hop joins to (parent in the chain)
              "to_pk_column": str,   # to_model's actual primary key column name (resolved once in
                                     # Python at translate-time — never hardcode "id" in a template)
          },
          # ... one entry per hop, in order from this entity up to (but not including) root_model
      ],
      "identity_source": {"type": "auth_user"} | {"type": "header", "header_name": str},
      "bypass_roles": List[str],     # [] if none declared
  }
  ```
  An entity with no ownership involvement at all has `entity["rls"] = None` (the key is always
  present, valued `None` — never omitted; every template checks it with a plain `{% if entity.rls %}`).
  Every `owned_relationships` entry for the relationship that IS this entity's `owner: true` or
  `cascades_ownership: true` relationship gains one extra key, `is_rls_link: bool` (`True` for that
  one entry, `False` for every other entry) — added in Task 3 alongside `rls` itself, consumed by
  Tasks 6-8 to distinguish the RLS-governing FK from an entity's other, ordinary owned relationships.
- **ERD schema additions (Task 1), copied verbatim from spec §3.1 — every task after Task 1 inherits these without re-deriving them:**
  1. At most one `owner: true` relationship per entity, and at most one `cascades_ownership: true`
     relationship per entity. An entity may have neither, or exactly one of the two — never both.
  2. `owner: true` and `cascades_ownership: true` are valid only on many-to-one relationships.
  3. Any entity carrying `owner: true` must declare an `rls:` block with `identity_source`.
  4. `identity_source.type: auth_user` requires `auth.enabled: true` **and** the `owner: true`
     relationship's `target` to be exactly `User`.
  5. `identity_source.type: header` requires `header_name` to be set. Independent of `auth.enabled`;
     `target` can be any entity, `User` included.
  6. `header_name` must not case-insensitively equal `Authorization`.
  7. `rls.bypass_roles`, if present, requires `rbac.enabled: true` (which itself requires
     `auth.enabled: true`, per the existing check at `backend/erd/loader.py:46-48`) — so
     `bypass_roles` is only reachable through the `auth_user` identity source. Every role listed
     must be a declared role in `rbac.roles`.
  8. `cascades_ownership: true` chains must terminate at an `owner: true` entity with no cycles,
     and every entity must resolve to at most one ownership path (ambiguous multi-path chains are
     rejected).
  Rules 1, 2, and 6 are enforced at the Pydantic level in `backend/erd/schema.py` (Task 1) — they
  need no cross-entity knowledge. Rules 3, 4, 5, 7, and 8 need the full `ERDConfig` and are enforced
  in `backend/erd/loader.py`'s `_validate_semantics` (Task 2, rule 8's cycle/ambiguity check) /
  `backend/erd/translate.py` (Task 3, rule 8's actual resolution — the loader only rejects
  structurally-impossible chains it can detect without full resolution; Task 3's resolver is the
  final authority and raises `ERDValidationError` itself if it discovers a cycle or ambiguity the
  loader's cheaper check missed. See Task 2 and Task 3 for the exact division.).
- **Non-owner single-row access is 404, not 403** (indistinguishable from the row not existing) —
  this falls out for free once `get_<entity>_by_id` takes `owner_id` and the existing
  `if item is None: raise HTTPException(status_code=404, ...)` route logic is unchanged.
- **A cascade-owned `create`/`update` whose linking FK references a row that exists but isn't owned
  by the caller gets the same 400 as a genuinely nonexistent FK** — both go through the same
  `ValueError` → `HTTPException(400, ...)` path already in `module_routes.py.jinja`'s
  `try:`/`except ValueError:` block for entities with `owned_relationships`.
- **Async/sync branching conventions** (all four touched template files already have real,
  merged sync/async branches from the async-support plan — every new piece of RLS logic below must
  be inserted into **both** existing branches, never just one):
  - `repo.py.jinja`: full per-function `{% if project.database_config.async_mode %}...{% else %}...{% endif %}` (unchanged from the async-support plan's convention) — RLS additions go inside both branches of each touched function.
  - `module_service.py.jinja` / `module_routes.py.jinja`: surgical inline tokens (`{{ 'async ' if is_async }}`, `{{ 'await ' if is_async }}`) — RLS additions follow the same idiom, not a duplicated block.
  - `module_schemas.py.jinja`: no sync/async branching exists in this file today (schemas are identical either way) and RLS's schema-layer change doesn't introduce any — it's a pure Jinja `{% if %}` on `rel.is_rls_link`, orthogonal to `is_async`.
- **Do not introduce Jinja macros anywhere** (this codebase has never used them, consistent with the async-support plan's constraint).
- **Every template change must be verified by actually rendering against a real fixture and reading the output** — not just eyeballing the template source. `ast.parse`/`py_compile` alone does not catch a merged-together field list, a wrong loop filter, or a missing `owner_id` thread-through — only outright syntax errors.
- **`repo.create_<entity>` needs zero changes in this entire plan.** If a task's implementer finds themselves wanting to add an `owner_id` parameter to a repo `create_*` function, stop and re-read Task 6 — the owner value is injected into the `data` dict at the *service* layer (root-owned) or validated via the *parent's own* filtered `get_by_id` (cascade-owned) before `repo.create_<entity>(db, data)` is ever called; the INSERT itself never needs a `WHERE`-style filter.
- **`Header` values arrive as strings; the identity column is an integer PK in every fixture this plan uses.** FastAPI's `Header(..., alias="X-Tenant-Id")` parameter is typed `int` in the generated route signature so FastAPI performs the conversion (and the native 422) automatically — never parse the header value manually in application code.

```python
from pydantic import BaseModel, Field, field_validator, model_validator
from typing import Literal


class RelationshipDecl(BaseModel):
    """A relationship declared from one entity to another.

    Only one side needs to declare it; `translate.py` fills in the other side.
    """
    name: str
    cardinality: Cardinality
    target: str
    attribute: Optional[str] = None
    target_attribute: Optional[str] = None
    foreign_key_column: Optional[str] = None
    nullable: bool = True
    unique: bool = False
    ondelete: Optional[str] = None
    lazy: Optional[LazyStrategy] = None
    cascade: Optional[str] = None
    association_table: Optional[str] = None
    owner: bool = False
    cascades_ownership: bool = False

    @model_validator(mode="after")
    def owner_and_cascades_ownership_are_valid(self) -> "RelationshipDecl":
        if self.owner and self.cascades_ownership:
            raise ValueError(
                f"relationship '{self.name}': cannot set both 'owner: true' and "
                "'cascades_ownership: true' — a relationship either IS the ownership column "
                "(owner) or passes ownership through from its target (cascades_ownership), never both."
            )
        if (self.owner or self.cascades_ownership) and self.cardinality != Cardinality.MANY_TO_ONE:
            flag = "owner" if self.owner else "cascades_ownership"
            raise ValueError(
                f"relationship '{self.name}': '{flag}: true' is only valid on a many-to-one "
                f"relationship (got cardinality '{self.cardinality.value}') — a row can have "
                "exactly one owner, which one-to-many/one-to-one/many-to-many don't resolve to."
            )
        return self
```

Add `RLSIdentitySource` and `RLSSpec` (new classes, placed after `RBACSpec` and before
`RelationshipDecl` so `EntitySpec` below can reference `RLSSpec` in source order):

```python
class RLSIdentitySource(BaseModel):
    type: Literal["auth_user", "header"]
    header_name: Optional[str] = None

    @model_validator(mode="after")
    def header_name_required_and_valid_for_header_type(self) -> "RLSIdentitySource":
        if self.type == "header":
            if not self.header_name:
                raise ValueError(
                    "rls.identity_source: type 'header' requires 'header_name' to be set "
                    "(e.g. 'X-Tenant-Id')"
                )
            if self.header_name.strip().lower() == "authorization":
                raise ValueError(
                    "rls.identity_source.header_name: must not be 'Authorization' (case-insensitive) "
                    "— this codebase's generated auth already relies on that header for the "
                    "'Bearer <token>' JWT scheme"
                )
        return self


class RLSSpec(BaseModel):
    identity_source: RLSIdentitySource
    bypass_roles: List[str] = Field(default_factory=list)
```

Add `rls: Optional[RLSSpec] = None` to `EntitySpec`, and a model validator enforcing the
at-most-one-per-entity half of rule 1 (the mutual-exclusion-per-relationship half is already
enforced above, in `RelationshipDecl` itself):

```python
class EntitySpec(BaseModel):
    name: str = Field(..., min_length=1)
    table_name: Optional[str] = None
    fields: List[ModelField] = Field(default_factory=list)
    relationships: List[RelationshipDecl] = Field(default_factory=list)
    endpoints: EndpointSpec = Field(default_factory=EndpointSpec)
    rls: Optional[RLSSpec] = None

    @model_validator(mode="after")
    def at_most_one_owner_and_one_cascades_ownership_relationship(self) -> "EntitySpec":
        owner_rels = [r.name for r in self.relationships if r.owner]
        cascade_rels = [r.name for r in self.relationships if r.cascades_ownership]
        if len(owner_rels) > 1:
            raise ValueError(
                f"entity '{self.name}': more than one relationship has 'owner: true' "
                f"({', '.join(owner_rels)}) — an entity can have exactly one ownership column."
            )
        if len(cascade_rels) > 1:
            raise ValueError(
                f"entity '{self.name}': more than one relationship has 'cascades_ownership: true' "
                f"({', '.join(cascade_rels)}) — an entity can inherit ownership through exactly "
                "one path."
            )
        return self
```

In `backend/erd/loader.py`, inside `_validate_semantics`, after the existing
`known_entities = ...` line and before the `for entity in erd.entities:` loop that validates

```python
def _validate_rls(erd: ERDConfig, known_entities: set) -> None:
    owner_targets: Dict[str, str] = {}  # entity name -> its owner:true relationship's target
    for entity in erd.entities:
        owner_rel = next((r for r in entity.relationships if r.owner), None)
        if owner_rel is None:
            continue
        owner_targets[entity.name] = owner_rel.target

        if entity.rls is None:
            raise ERDValidationError(
                f"Entity '{entity.name}': relationship '{owner_rel.name}' has 'owner: true' but "
                f"the entity declares no 'rls:' block — every 'owner: true' entity must declare "
                "'rls: {identity_source: ...}'."
            )

        source = entity.rls.identity_source
        if source.type == "auth_user":
            if not erd.auth.enabled:
                raise ERDValidationError(
                    f"Entity '{entity.name}': rls.identity_source.type 'auth_user' requires "
                    "auth.enabled: true (there is no JWT-authenticated caller to resolve "
                    "ownership from otherwise)."
                )
            if owner_rel.target != "User":
                raise ERDValidationError(
                    f"Entity '{entity.name}': rls.identity_source.type 'auth_user' requires the "
                    f"'owner: true' relationship's target to be 'User' (got '{owner_rel.target}') "
                    "— auth_user resolves ownership from the JWT-authenticated User; a different "
                    "owner entity needs rls.identity_source.type: header instead."
                )

        if entity.rls.bypass_roles:
            if not erd.rbac.enabled:
                raise ERDValidationError(
                    f"Entity '{entity.name}': rls.bypass_roles requires rbac.enabled: true "
                    "(bypass roles are RBAC roles)."
                )
            unknown = sorted(set(entity.rls.bypass_roles) - set(erd.rbac.roles))
            if unknown:
                raise ERDValidationError(
                    f"Entity '{entity.name}': rls.bypass_roles references unknown role(s): "
                    f"{', '.join(unknown)} — declared roles are: "
                    f"{', '.join(erd.rbac.roles) or 'none declared'}."
                )

    for entity in erd.entities:
        cascade_rel = next((r for r in entity.relationships if r.cascades_ownership), None)
        if cascade_rel is None:
            continue
        # Walk up the cascades_ownership chain (bounded by len(erd.entities) to avoid an
        # infinite loop on a cycle here too - Task 3's resolver gives the authoritative,
        # precise cycle error; this is a coarser, cheaper pre-check).
        current = cascade_rel.target
        seen = {entity.name}
        steps = 0
        by_name = {e.name: e for e in erd.entities}
        while steps <= len(erd.entities):
            if current in owner_targets:
                break  # reached a root-owned entity - structurally valid
            if current in seen or current not in by_name:
                raise ERDValidationError(
                    f"Entity '{entity.name}': relationship '{cascade_rel.name}' "
                    f"(cascades_ownership: true, target '{cascade_rel.target}') does not lead to "
                    "any entity with 'owner: true' — either the chain doesn't terminate at an "
                    "owned entity, or it cycles back on itself."
                )
            seen.add(current)
            next_entity = by_name[current]
            next_cascade = next((r for r in next_entity.relationships if r.cascades_ownership), None)
            if next_cascade is None:
                raise ERDValidationError(
                    f"Entity '{entity.name}': relationship '{cascade_rel.name}' "
                    f"(cascades_ownership: true, target '{cascade_rel.target}') does not lead to "
                    "any entity with 'owner: true' — either the chain doesn't terminate at an "
                    "owned entity, or it cycles back on itself."
                )
            current = next_cascade.target
            steps += 1
        else:
            raise ERDValidationError(
                f"Entity '{entity.name}': relationship '{cascade_rel.name}' "
                f"(cascades_ownership: true, target '{cascade_rel.target}') does not lead to "
                "any entity with 'owner: true' — either the chain doesn't terminate at an "
                "owned entity, or it cycles back on itself."
            )
```

```python
def _resolve_rls(erd: ERDConfig, data_models: Dict[str, Dict[str, Any]]) -> None:
    """Resolve every entity's ownership (unowned / root-owned / cascade-owned), attaching
    `rls` (the structure documented in the RLS plan's Global Constraints) to every model in
    `data_models`, and marking exactly the RLS-governing relationship's `is_rls_link: True`
    inside that model's `owned_relationships`. Must run after `owned_relationships` has been
    populated on every model (reads `model["owned_relationships"]`), before `crud_entities`
    is built (which copies `data_models[...]["owned_relationships"]` and needs `rls` too).
    """
    for model in data_models.values():
        model["rls"] = None
        for rel in model["owned_relationships"]:
            rel["is_rls_link"] = False

    entity_by_name = {e.name: e for e in erd.entities}

    def owner_rel_of(model_name: str) -> Any:
        model = data_models.get(model_name)
        if model is None:
            return None
        return next((r for r in model["owned_relationships"] if r["owner"]), None)

    def cascade_rel_of(model_name: str) -> Any:
        model = data_models.get(model_name)
        if model is None:
            return None
        return next((r for r in model["owned_relationships"] if r["cascades_ownership"]), None)

    def pk_column_of(model_name: str) -> str:
        model = data_models[model_name]
        pk_field = next((f for f in model["fields"] if f.get("primary_key")), None)
        return pk_field["name"] if pk_field else "id"

    def resolve(model_name: str, visiting: frozenset) -> Any:
        model = data_models.get(model_name)
        if model is None:
            return None
        if model["rls"] is not None:
            return model["rls"]

        owner_rel = owner_rel_of(model_name)
        if owner_rel is not None:
            entity = entity_by_name[model_name]
            rls = {
                "is_root": True,
                "root_model": model_name,
                "owner_fk_column": owner_rel["fk_column"],
                "join_chain": [],
                "identity_source": entity.rls.identity_source.model_dump(mode="json"),
                "bypass_roles": list(entity.rls.bypass_roles),
            }
            model["rls"] = rls
            owner_rel["is_rls_link"] = True
            return rls

        cascade_rel = cascade_rel_of(model_name)
        if cascade_rel is None:
            return None

        if model_name in visiting:
            raise ERDValidationError(
                f"Entity '{model_name}': its cascades_ownership chain has a cycle - it "
                "eventually leads back to itself instead of terminating at an owner:true entity."
            )

        parent_name = cascade_rel["target_model"]
        parent_rls = resolve(parent_name, visiting | {model_name})
        if parent_rls is None:
            raise ERDValidationError(
                f"Entity '{model_name}': cascades_ownership relationship targets '{parent_name}', "
                "which does not resolve to any owner:true entity."
            )

        hop = {
            "from_model": model_name,
            "from_fk_column": cascade_rel["fk_column"],
            "to_model": parent_name,
            "to_pk_column": pk_column_of(parent_name),
        }
        rls = {
            "is_root": False,
            "root_model": parent_rls["root_model"],
            "owner_fk_column": parent_rls["owner_fk_column"],
            "join_chain": [hop] + parent_rls["join_chain"],
            "identity_source": parent_rls["identity_source"],
            "bypass_roles": parent_rls["bypass_roles"],
        }
        model["rls"] = rls
        cascade_rel["is_rls_link"] = True
        return rls

    for model_name in list(data_models.keys()):
        resolve(model_name, frozenset())
```

**Design note — `require_roles(...)` as a named parameter, not just a decorator dependency:**
`require_roles(...)` (in `rbac/dependency.py.jinja`) already returns the authenticated `User` —
today's routes only ever use it inside `dependencies=[Depends(require_roles(...))]`, which runs it
for its 403-raising side effect but discards the return value (FastAPI doesn't inject a
`dependencies=[]` entry's result into the function body). An RLS-affected, `auth_user`-sourced
route needs the actual `User` object inside the handler body (to read `.roles` for the bypass
check and `.id` for `owner_id`), so this task makes `current_user: User = Depends(require_roles(...))`
a **named function parameter** instead, for exactly those entity+action combinations — same call,
same 403 behavior, now also exposing the result. The decorator's separate
`dependencies=[Depends(require_roles(...))]` line is **suppressed** for those same combinations
(rendering it too would evaluate `require_roles(...)` twice per request, redundant and wasteful).
Every action that is RBAC-gated but NOT RLS-affected (or RLS-affected via `header`, not
`auth_user`) keeps today's decorator-only form, completely unchanged.

**Design note — a fixed Python parameter name for the header identity source:** the HTTP header
name (e.g. `X-Tenant-Id`) is not a valid Python identifier, but it doesn't need to be one —
FastAPI's `Header(..., alias="X-Tenant-Id")` maps an arbitrary HTTP header to any Python parameter
name you choose via `alias`. Every header-sourced route uses the same fixed name,
`rls_owner_header`, regardless of the actual header string — no snake-casing/derivation needed.

**Known, accepted minor limitation:** `has_owned_rel` (the existing flag gating this file's
`Optional` import) is intentionally left unchanged — it still counts an `is_rls_link` relationship
as "this module has an owned relationship." In the narrow case where a module's *only*
`owned_relationships` entries are `is_rls_link` ones (i.e. the module has RLS-affected entities but
no *other* client-filterable FK relationships at all), `Optional` gets imported but goes unused in
that generated file. This is a cosmetic (unused-import) issue, not a functional one — accepted
rather than adding a materially more complex Jinja aggregate to close a gap with no behavioral
impact. Flag it in review if you disagree, but don't block on it.

seems contradictory: **the filter only ever fires for a *root*-owned entity's owner relationship,

condition is `rel.is_rls_link and entity.rls.is_root`, not `rel.is_rls_link` alone — mirroring
